## Сценарий демонстрации

Показ занимает 45 секунд на слайде 10. Демонстрируется demo-модель стенда, а не основная
модель (#9). Варианты выбираются заранее, до защиты.

### A. Живой Compose-стенд

Нужна машина с Docker Engine и Compose v2. Сборка образа долгая, поэтому стенд поднимается
**до защиты** по разделам 1–3 [маршрута стенда](../../containers/README.md), а на защите
выполняется раздел 4.

| Шаг | Что показывает выступающий | Что увидит преподаватель | Подтверждение в репозитории |
|---|---|---|---|
| 1 | `curl http://127.0.0.1:15001/healthz` | `target_db=ok`, `monitor_db=ok` | [containers/README.md](../../containers/README.md), раздел 3 |
| 2 | `scripts.live_demo --ticks 3` (нормальные тики) | Новые оценки, `is_anomaly=0` | там же, раздел 4 |
| 3 | `scripts.live_demo --ticks 3 --incident-at 2` | Инъекция (`★ INCIDENT`) и новая оценка с `is_anomaly=1` | там же, раздел 4 |
| 4 | `/dashboard/inference` (учебный вход `demo@dbmonitor.app`) | Источник, версия модели, отметка demo, новая оценка | там же, раздел 4 |

Заранее сказать: примерно в одном показе из 20 нормальный тик даёт ложную тревогу
(190 / 200 на test demo-модели). Если это случилось, назвать это ограничением модели и не
перезапускать сценарий ради «чистого» результата. Ручной прогон стенда по этому маршруту в
рамках #20 **не выполнялся**: в среде подготовки нет Docker. Независимый прогон стенда
(#13, критерий 7) тоже не выполнен.

### B. Тот же сценарий без Docker (около 45 секунд)

Нужны Python 3.12 и зависимости `requirements-dev.txt`. Сценарий запускает настоящие
адаптер и сервис FastAPI (ASGI test client) на временной SQLite, без сети и внешних
сервисов ([описание](../../monitoring/model/README.md), раздел 5). Вывод не записывать
поверх файлов репозитория:

```bash
python -m scripts.check_model_quality_alert > /tmp/model-alert.json 2> /tmp/model-alert.log
echo $?   # 0 — все проверки прошли
python -c "import json; d = json.load(open('/tmp/model-alert.json')); \
print(d['passed'], sum(d['checks'].values()), len(d['checks']), d['events'])"
```

Ожидается: код 0, `True 19 19`, `firing` на тике 33 и `resolved` на тике 54; в
`/tmp/model-alert.log` — строка `alert ModelAnomalyRateHigh firing`. Команду запускать во
время слайдов 8–9 или прямо перед защитой и говорить, когда она была выполнена. Проверено
13.11.2026 на `master` `89dec70`: код 0, 47 секунд, 19 из 19 проверок, хронология (тик,
фаза, score, флаги, состояние алерта) совпала с сохранённым `demo.json`.

## Вероятные вопросы

| Вопрос | Короткий ответ |
|---|---|
| Модель нашла все инциденты — почему она не допущена? | Критерий FPR ≤ 10 % зафиксирован до экспериментов. На test 240 ложных сигналов из 1 809 нормальных наблюдений, 13,27 %; precision по наблюдениям 27,71 % |
| Почему не взять `contamination=0,005` с меньшим FPR? | Выбор делался только по validation: максимальный F1 среди конфигураций, выполнивших цели. Подбор по test протокол запрещает — это утечка test |
| Почему FPR вырос с 8,84 % до 13,27 %? | Гипотеза: `row_count` растёт со временем и выходит из диапазона обучения. Это не доказано; нужны признаки, устойчивые к росту таблиц, и новый закрытый test |
| Чем demo-модель отличается от основной? | Обучена по отдельному протоколу на режиме стенда, помечена `demo=true`, `quality_admitted=false`. Её FPR 1,66 % относится к её собственному test и не улучшает результат #9 |
| Почему Isolation Forest? | Нет меток инцидентов, признаки числовые, обучение быстрое. Сигнал модели — повод для проверки человеком |
| Как выпустить новую версию и откатиться? | Реестр с явным выбором версии и допуском реализован. Blue-green, shadow / canary и откат описаны в стратегии, но не испытаны; `release.yml` не запускался |
| Как вы узнаете о деградации модели? | Алерт `ModelAnomalyRateHigh`, распределение score, признак `conclusive`; стратегия дрейфа KS / PSI описана и проверена синтетически, но не автоматизирована |
| Как проверяли код, написанный ИИ? | Принимали только с командой, тестом или артефактом и ревью другого участника. Примеры: исправленная граница инцидента (#10), доработка стратегии дрейфа (#17) |
| Что проверяет CI? | Unit и контракты на Python 3.11–3.13, интеграцию с пятью хранилищами и Compose-сценарий, Ruff; E2E — при push в master |

## Сборка и проверка

Сборка воспроизводится во временном venv вне репозитория. LibreOffice в среде подготовки
нет, поэтому PDF рисуется из `.pptx` собственным рендером через headless Chromium.
Arial и Courier New заменяются метрически совместимыми Liberation Sans и Liberation Mono
(SIL OFL), поэтому переносы строк совпадают с PowerPoint.

```bash
python -m venv /tmp/deck-venv && /tmp/deck-venv/bin/pip install python-pptx==1.0.2
/tmp/deck-venv/bin/python docs/course/final/presentation/build_presentation.py
/tmp/deck-venv/bin/python docs/course/final/presentation/render_pdf.py \
  --chromium <путь к headless Chromium> --font-dir <каталог liberation-fonts-ttf-2.1.5>
```

`render_pdf.py` завершается ошибкой, если текст не помещается в свою рамку; флаг `--draft`
печатает PDF с перечнем таких рамок для просмотра.

Проверено 13.11.2026: python-pptx 1.0.2, Chromium 141.0.7390.37 (headless shell),
Liberation Fonts 2.1.5.

- PPTX: 11 слайдов 13,333 × 7,5 дюйма (16:9), заметки на каждом слайде; файл заново
  открыт python-pptx и прошёл валидатор OOXML (схема, связи, типы содержимого).
- PDF: 11 страниц 13,333 × 7,5 дюйма; все шрифты встроены (Liberation Sans / Mono),
  кириллица извлекается как текст; все текстовые рамки помещаются.
- Все 11 страниц отрисованы в PNG и просмотрены: нет обрезанного текста, наложений и
  нечитаемых таблиц.
- В презентации нет секретов, токенов, паролей и сведений о среде подготовки. Учебный
  логин стенда (без пароля) упомянут только в этом README; полностью вход описан в
  [маршруте стенда](../../containers/README.md).

Ограничения проверки: `.pptx` не открывался в Microsoft PowerPoint и LibreOffice — их нет
в среде подготовки. PDF совпадает с `.pptx` по геометрии и тексту, но построен не
PowerPoint. Перед защитой нужно открыть `.pptx` в PowerPoint на демонстрационном
компьютере и пролистать все слайды.
