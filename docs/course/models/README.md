# Версии моделей — задача #5

Реализован локальный реестр неизменяемых пар **StandardScaler + Isolation Forest**.
Он связывает выбранную модель с кодом, данными, параметрами и схемой признаков.
Обучение/сохранение кандидата не переключает рабочую версию. Загрузка и
предсказание не вызывают fit и не подставляют последний joblib.

## Что сохраняется

Каждая версия лежит в `models/registry/versions/if-<SHA-256>/`:

- `pipeline.skops` — модель и её scaler в одном артефакте, с общей контрольной суммой;
- `manifest.json` — ID версии, полный source, версия/хеш/описание признаков,
  git SHA и хеши исходников, dataset ID и хеш обучающих данных, seed, параметры,
  фактическое время нового обучения, MLflow run_id при его наличии, окружение и
  результат оценки. Отдельно сохраняется происхождение импортированного артефакта.

ID версии — SHA-256 канонического манифеста без самого ID, включая хеш артефакта.
Поэтому одна версия не получает новые веса, scaler или метаданные. Повторный
импорт тех же байтов идемпотентен; повреждённая существующая версия не затирается.
Рабочие указатели хранятся отдельно по хешу полного source
`(project_id, connection_id, schema_name, table_name)`. Выбор версии одного
подключения не распространяется на одноимённую таблицу другого подключения.

Перед десериализацией проверяются ID манифеста, source, версия/хеш схемы и SHA-256
**тех же байтов**, которые будут загружены. Затем проверяются типы, обученность,
число признаков, seed и параметры модели. Допускаются только Pipeline из
StandardScaler/IsolationForest и известный тип `sklearn.tree._tree.Tree`;
список неизвестных типов не превращается автоматически в список доверенных.
Новый реестр не загружает pickle/joblib. Требуется записанная версия scikit-learn;
остальное окружение сохраняется для воспроизведения и должно восстанавливаться
при расхождениях. Проверенная совместимость не обещается для произвольных версий.

Каталог реестра и доказательства оценки обслуживаются доверенным оператором.
Хеши обнаруживают повреждение, но не являются цифровой подписью: человек с правом
записи всего реестра может переписать и файлы, и метаданные. Это локальный инструмент,
не HTTP-сервис авторизации; доступ пользователя/адаптера реализуется в #12.

## Воспроизвести сохранённую модель #9

После установки `requirements-dev.txt` (включает course-зависимости):

```bash
python -m scripts.model_versions --registry models/registry stage-export \
  --source docs/course/models/source.example.json > /tmp/course-model-manifest.json
```

В выводе есть `model_version`. Для следующих команд замените `MODEL_VERSION`
на этот ID (полностью, включая `if-`). Source в примере — **демонстрационная
привязка синтетического benchmark**, а не существующее подключение пользователя.
Импорт проверяет закреплённый SHA-256 архива и аудит замороженных предсказаний,
не обучает модель, не меняет архив и не создаёт новые MLflow-runs.

```bash
python -m scripts.model_versions --registry models/registry inspect \
  --source docs/course/models/source.example.json --version MODEL_VERSION --demo
python -m scripts.model_versions --registry models/registry activate \
  --source docs/course/models/source.example.json --version MODEL_VERSION --demo
python -m scripts.model_versions --registry models/registry predict \
  --source docs/course/models/source.example.json \
  --features docs/course/models/features.example.json --demo
```

`predict` без `--version` использует явный указатель данного source/режима.
С `--version MODEL_VERSION` можно восстановить конкретную версию без переключения.
Ответ содержит фактические `model_version`, `feature_schema_version`, source и score.
Отсюда через манифест находятся код, данные и MLflow-run. Эти команды ещё не
добавляют версии в существующий Flask API: адаптер, FastAPI и хранение scores — #12.

**Baseline не допущена:** её FPR 13,27% выше 10%. Обычная команда `activate`
без `--demo` завершится кодом 2; рабочий указатель не изменится. Демо-указатели
лежат в `demo-active/`, обычные — в `active/`; загрузка обычной версии никогда
не переключается на демо автоматически. `--demo` явно разрешает изучение
отклонённого/неоценённого кандидата, не объявляет его качественным.

В архиве fit выполнен до начала validation-run. Точное время завершения fit
тогда не записывалось: `trained_at=null`, `time_status=not_recorded_in_historical_export`.
Версия схемы `1.0.0` фиксируется при импорте как проверенная совместимая схема,
а не выдаётся за поле, якобы сохранённое в старом MLflow-run.
Время сериализации из MLmodel записано отдельно как `artifact_created_at`.
Оно не выдаётся за время обучения. Сохранён training-associated validation run_id
`269a806a...`; final_test run_id `36db7cd8...` находится в evaluation/origin.
Полные значения сохранены в манифесте. Новое обучение записывает реальные
`training_started_at` и `trained_at`; MLflow run_id не выдумывается, если MLflow не использовался.

## Новое обучение и явный допуск

`train --snapshot snapshot.json` принимает объект с `source`, `row_counts` и
`null_rates`; каждый ряд состоит из `{"ts": "...+00:00", "value": число}`.
Снимок должен содержать проверенные канонические timestamps одного источника.
Нужно не менее 200 векторов после совмещения/вычисления дельт. Перед записываемым
обучением CLI требует чистое рабочее дерево Git. Dataset ID хеширует канонический
снимок с source; записываются текущий git SHA, хеши кода, seed, параметры и время.
`--run-id` можно передать, только если соответствующий MLflow-run реально существует.
Команда создаёт **неоценённого кандидата**, без изменения любого активного указателя.

`stage-local --source source.json --pipeline pipeline.skops --training training.json
--evaluation evaluation.json` сохраняет готовый локальный артефакт с доказательствами
обучения и оценки; Python-эквивалент — `ml.model_registry.stage_bytes`.
Оценка должна содержать `split: test`, `data_sha256`, `metrics` с event_recall/FPR/
abrupt_median_delay_ticks. Хеш test не должен совпадать с хешем train. При наличии
`overall_metrics` проверяются также общие метрики. Один флаг `passed: true` не даёт
допуска. Порог: recall ≥80%, FPR ≤10%, медиана резких событий ≤1 тик; значения должны
быть конечными числами. После записи артефакт и эта оценка связаны одним ID манифеста.

Оператор отвечает за соответствие отчёта **именно этому артефакту** и независимость
проверки: разные хеши сами по себе не доказывают отсутствие утечки между выборками.
Общая функция проверяет формат и пороги; она не заменяет эксперимент/разметку.
Архив #9 проверяется отдельно по сохранённым предсказаниям и фиксированной контрольной сумме.
Новая серия экспериментов этой задачей не проводится и не получает фиктивного PASS.

Для допуска используется явная команда `activate --source ... --version ...`.
Она сначала полностью проверяет артефакт, затем атомарно заменяет один указатель.
Для отката повторяется та же команда с **предыдущим ID**: восстанавливается
та же схема и та же пара модель/scaler, без обучения и удаления других версий.
Ошибка проверки оставляет прежний указатель. Историю scores этот инструмент
не меняет; версионный ключ, миграции SQLite/PostgreSQL и выбор версии в дашборде — #12.

## Совпадение признаков и совместимость

`ml/features.py` содержит общую версию схемы `1.0.0`, порядок признаков,
`build_rows` и `build_vector`. Они используются новым обучением, существующим
загрузчиком детектора и одиночным предсказанием по паре наблюдений. Пропущенная
предыдущая точка не превращается в нули; дельты берутся от предыдущей согласованной
точки, без деления на время. Функция не читает БД и не обучает scaler.

Исторический генератор #7 и архив #9 не переписывались. В архивных CSV d_null_rate
округлялась до 6 знаков; при восстановлении используются записанные значения.
Тест подтверждает совпадение всех 672 сохранённых test-scores таблицы orders с
точностью 1e-12. Старый joblib формата `{model, scaler, trained_at, n_points}`
по-прежнему загружается существующим детектором; ему не приписываются новые
версии/источник автоматически. Ночной scheduler пока остаётся в legacy-контуре.
Его переключение на кандидатов реестра и новый сервис входит в #12.

Версия модели — `if-<SHA-256>`; версия данных — dataset ID/хеш снимка; версия
признаков — `1.0.0`; версия будущего API — `/v1/` из [контракта #4](https://github.com/aleksandr-novikov/ai-integration-development/pull/36).
Они не выводятся друг из друга. Обновление API не переименовывает старую модель.

## Проверки

```bash
python -m pytest -q tests/test_model_registry.py tests/test_anomaly_detector.py \
  tests/test_model_quality.py tests/test_quality_report.py
ruff check .
```

Проверяются воспроизводимость сохранённых scores, происхождение, общие признаки,
старый joblib, запрет fit при загрузке, изоляция источников, отсутствие/повреждение
артефакта, явный допуск/демо, переключение и откат без потери версий.
Тесты нормального допуска используют **искусственные PASS-метрики только внутри
временных unit-фикстур**; они не являются результатами качества реальной модели.

Локально 25.10.2026: **163 passed** (реестр, старый детектор, качество, генератор,
валидация данных, scheduler и изоляция проектов); Ruff и `pip check` прошли.
Сохранены предупреждения joblib о NumPy 2.5. CLI проверен на неизменном экспорте:
обычная активация вернула 2, демо-активация и предсказание — 0.
