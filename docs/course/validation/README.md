# Валидация ML-датасета — задача #8

Используем pandas 2.2.3: вариант прямо допускается лекцией В06 (слайды 35–39, 45). Для трёх небольших CSV достаточно явных проверок и переносимого JSON-отчёта; отдельный сервис и конфигурация Great Expectations не нужны. Это проверка входа учебного ML-пайплайна, а не функция мониторинга пользовательских БД.

## Запуск перед обучением

Из корня репозитория, после установки `requirements.txt` и генерации датасета:

```bash
python -m scripts.generate_ml_dataset --output data/course
python -m scripts.validate_ml_dataset --dataset data/course --report /tmp/course-validation.json
```

Код завершения: **0 — все проверки пройдены, 1 — данные не прошли валидацию, 2 — неверные аргументы CLI**. Датасет читается без изменений; отчёт должен лежать вне его каталога. В задаче #9 запуск экспериментов должен зависеть от успешного завершения этой команды (например, через `&&`). Сам по себе текущий валидатор не перехватывает вызовы существующего промышленного детектора.

## Что проверяем

| Проверка | Условие |
|---|---|
| Манифест и целостность | Конфигурация, список признаков/таблиц, dataset_id, SHA-256 трёх CSV и incidents.json |
| Схема каждого CSV | Файл читается, не пуст, содержит ровно ожидаемые столбцы в ожидаемом порядке |
| Идентификаторы | project_id совпадает с конфигурацией; table_name входит в перечень таблиц |
| Типы и конечность | Четыре признака числовые, без пропусков, NaN и ±inf |
| Диапазоны | null_rate ∈ [0,1], row_count — целое число ≥ 0 |
| Время | ISO 8601 с явным UTC (`Z` или `+00:00`) |
| Уникальность | Нет повторов (project_id, table_name, ts), в том числе между выборками |
| Порядок | В исходном порядке CSV время каждого ряда строго возрастает |
| Разделение выборок | max(train.ts) < min(validation.ts), max(validation.ts) < min(test.ts) |
| Временная сетка признаков | Каждая таблица имеет ровно все ожидаемые тики своей выборки согласно конфигурации |
| Согласованность дельт | Изменение row_count/null_rate совпадает с предыдущим наблюдением того же ряда, включая границы выборок; абсолютный допуск 10⁻⁶ |
| Разметка | Интервалы инцидентов читаются, непусты, не пересекаются внутри ряда; incident_id и is_anomaly соответствуют интервалам; train нормальный |

Получается 20 результатов проверок на корректном наборе. При повреждённой схеме зависимые проверки не выполняются для непрочитанных файлов; ошибка схемы всегда делает весь результат отрицательным. Аналогично проверка меток по интервалам выполняется только после проверки файла инцидентов. Это не означает, что непрочитанные данные прошли проверки.

Первая выгруженная точка каждого ряда не имеет выгруженного предшественника: её дельта проверяется только на тип и конечность. Числа и дельты остальных строк привязаны к единому ts строки; исходных времён отдельных SQL-измерений в этом синтетическом наборе нет. Валидатор не доказывает причинность генератора или отсутствие подбора модели по test: это обеспечивают протокол и отдельные тесты генерации/обучения.

## Сохранённые результаты и воспроизведение

```bash
python -m scripts.demo_dataset_validation --output docs/course/validation
python -m pytest tests/test_validate_ml_dataset.py tests/test_generate_ml_dataset.py tests/test_seed_metrics_db.py -q
```

Демонстрация создаёт временный датасет со стандартными параметрами, копирует его, вносит дефекты только в копию и удаляет временные CSV после проверки. Версия Python входит в dataset_id; для совпадения с приложенными отчётами используется Python 3.12.14. Сами отчёты не содержат временных путей или времени запуска.

- [valid.json](valid.json): исходный набор, 8 061 строка, **20 проверок пройдены, 0 провалены**.
- [corrupted.json](corrupted.json): намеренно испорченная копия, **14 проверок провалены**. Это учебная демонстрация, а не обнаруженные дефекты исходного генератора.

В validation.csv намеренно внесены: пустой project_id; текст вместо row_count; null_rate=1.5; отрицательный row_count; бесконечная d_null_rate; неразбираемое время и время без UTC; неверная d_row_count; ложная метка аномалии; перестановка двух наблюдений одного ряда; дубликат; строка, скопированная из train. Манифест оставлен прежним, поэтому дополнительно обнаруживается несовпадение SHA-256. Проверки содержимого продолжаются после ошибки хеша. Одно повреждение может нарушать несколько условий, поэтому суммы error_count нельзя считать числом независимых дефектов.

В каждом результате есть статус, полное число нарушений данной проверки и не более пяти примеров. Ссылки вида `validation.csv:2` обозначают номер записи CSV с учётом заголовка; для стандартного генератора это также физический номер строки. dataset_id в повреждённом отчёте — заявленный идентификатор исходного манифеста, не подтверждённая версия испорченной копии.

## Действия при ошибке

Остановить обучение и публикацию результатов эксперимента, сохранить отчёт вместе с версией данных. По примерам найти источник нарушения, исправить генератор/выгрузку или параметры, сформировать новый набор в новом каталоге и повторить валидацию. Не заполнять пропуски, не удалять выбросы и не пересчитывать хеши автоматически ради прохождения проверки. Если протокол данных изменился намеренно, согласовать его и обновить версию набора и проверки; старые отчёты экспериментов сохранять с прежним dataset_id.
