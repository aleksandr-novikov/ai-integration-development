# MLOps-roadmap DB Monitoring на 6 месяцев

**Старт — уровень 0–1.** Унаследованы сбор метрик, [ночное обучение IF][scheduler], CI/Docker, технический мониторинг. Учебные результаты: воспроизводимые данные, валидация, [5 MLflow-экспериментов + final_test][experiments], [проверки качества][quality]. Сквозных версий [модели][detector]/[score][storage], управляемой публикации и мониторинга качества IF нет; MLflow отделён от приложения. **FPR baseline — 13,27% при цели ≤10%: допуска нет.** Ночное обучение не означает ML CI/CD; исправность сервиса не доказывает качество модели.

**Границы:** [учебный минимум][course] — открытые #4/#5, #11–#17; #3 и #7–#10 закрыты. Ниже — план развития параллельно/после минимума, не сроки семестра. М1–М6 — месяцы от старта; роли функциональные, без персональных обязательств.

**Практики:** A — прослеживаемость данных/моделей; B — воспроизводимое обучение и контроль допуска; C — управляемый выпуск/откат; D — мониторинг и проверяемое переобучение.

| Месяц | Практика и действие (план) | Зависимость / роль | Проверяемый результат (план) |
|---|---|---|---|
| М1 | **A:** манифест версии (#4/#5) | Вход: #3, #7–#9; роль: ML-инженер | Манифест связывает модель/scaler, git SHA, dataset_id, run_id, схему/хеши; восстановлен фиксированный score. |
| М2 | **B:** пайплайн и gate; новый закрытый test (#11) | Вход: М1, #8/#10; роль: ML-инженер + QA | Gate отклоняет кандидата при провале данных/тестов или [целей CASE][case]: recall инцидентов ≥80%, FPR ≤10%, медиана задержки резких событий ≤1 цикла. Baseline отклоняется. |
| М3 | **C:** контракт и FastAPI (#12/#13) | Вход: М2, #4/#5/#11; роль: API-инженер | Контрактный тест подтверждает одинаковые признаки обучения/инференса, отказ несовместимой схеме без fit, сохранение источника и версии score ([ADR][adr]). |
| М4 | **C:** выпуск и откат (#14/#15) | Вход: М3, gate М2; роль: DevOps | Протокол переключения/отката восстанавливает прежнюю модель/score без потери истории; выпуск разрешён только после gate. |
| М5 | **D:** мониторинг (#16) | Вход: М4, разметка; роль: инженер данных + аналитик | Отчёт контролирует свежесть/качество входов, ошибки/latency, FPR/recall/задержку по версии и окну; без разметки — «нет оценки». |
| М6 | **D/B:** дрейф → расследование → кандидат (#17) | Вход: М5 → М2 → М4; роль: ML-инженер | Сценарий дрейфа с заданными baseline/окном/порогом проверяет предупреждение, расследование, обучение кандидата и повторный gate; автоматического выпуска нет. |

**Цель через полгода — уровень 1:** воспроизводимый логируемый пайплайн, обязательные проверки, версии и испытанный откат. Ночное обучение создаёт только кандидатов; решения о переобучении и выпуске ручные. Достижение ML-метрик не гарантируется. Уровень 2 избыточен для одного IF-кейса и четырёх участников без подтверждённой частоты релизов. Достаточен локальный/контейнерный запуск, облачный production для зачёта не требуется.

**Год без практик — риски:** A — утрата происхождения/воспроизводимости; B — выпуск некачественной модели; C — несовместимые признаки и ненадёжный откат; D — незамеченная деградация при исправном сервисе.
