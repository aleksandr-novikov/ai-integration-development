# Контракт ML API — задачи #4 и #12

Два документа разделяют legacy Flask API и отдельный сервис инференса.

| Спецификация | Маршруты | Реализация |
|---|---|---|
| [legacy.openapi.yaml](legacy.openapi.yaml) | GET /api/anomalies/{table_name}, GET /api/forecast/{table_name} | Существующий Flask |
| [inference.openapi.yaml](inference.openapi.yaml) | POST /v1/predict, POST /v1/model, GET /healthz | FastAPI, `inference.service` |

Исходный контракт одного ML-эндпоинта для ДЗ В03 подготовлен в #4.
В #12 добавлены работающий сервис, ещё два маршрута и проверки через Swagger UI.
[Запуск, адаптер, миграции и результаты проверок](../inference/README.md).
Архитектурная граница — [ADR-001](../../adr/001-flask-and-inference-service.md).

## Существующий Flask API

```bash
curl 'http://localhost:5001/api/anomalies/orders?range=7d'
curl 'http://localhost:5001/api/forecast/orders?metric=row_count&horizon=1d'
```

Аномалии читаются из сохранённых scores, без обучения. `200 []` не различает
неизвестную таблицу, пустую историю и отсутствие scores. `is_anomaly` — **0/1**,
`features` может отсутствовать. Отсутствие joblib не мешает чтению scores.
После миграции legacy-маршрут читает только результаты `legacy-unknown`;
опубликованные версии доступны отдельно через `/api/inference/scores`.

Прогноз требует `FF_FORECAST=true`. При выключенном флаге всегда HTML 404,
включая неправильные параметры. При включённом: неверные metric/horizon —
JSON 400, недостаточно истории — JSON 422 `insufficient_data`; сообщение
использует `orders/row_count`. Техническая ошибка может дать HTML 500.
Метрики прогноза — `row_count` и `size_bytes`, не `null_rate`.

Сохранённая модель используется повторно, если её `last_ts` отстаёт от
последней точки истории не более чем на час и последний changepoint не
изменился. Иначе, включая отсутствие модели, legacy может обучиться в запросе.
Отдельный FastAPI-сервис так не делает.

Сессия Flask-Login выбирает доступный проект; у этих двух legacy-маршрутов
сохранён анонимный fallback в `legacy`. Query `project_id` не переключает права.
Это не авторизация нового сервиса. Новые API адаптера и `/api/explain` требуют
сессию; существующий legacy fallback не предоставляет доступ к новым scores.

`/api/explain` и `POST /api/inference/predict` принимают JSON до 64 KiB и глубиной
до 32: иначе 413 `request_too_large` или 400 `invalid_json`. Для `/api/explain` без
`source` также возможны 409 `source_required`, 403 `source_forbidden` и 404, если
на момент `ts` наблюдений нет; [правила определения источника](../inference/README.md).

## Инференс и источник

Flask проверяет пользователя, членство в проекте, активное подключение и
разрешённую схему/namespace. Он читает историю одного источника и строит признаки
общей чистой функцией `ml.features.build_rows`, используемой и обучением.
FastAPI проверяет сервисный bearer-токен и его allowlist полного источника.

| Поле | Правило |
|---|---|
| source.project_id | ID проекта, не разрешение на доступ |
| source.connection_id | ID подключения внутри проекта, не DSN |
| source.schema_name | Точная схема; у Iceberg — полный effective namespace |
| source.table_name | Точное имя таблицы |
| observed_at / previous_observed_at | RFC 3339 с часовым поясом; предыдущая точка строго раньше текущей |
| model_version | Неизменяемый ID манифеста #5, не путь |
| feature_schema_version | Три компонента без ведущих нулей, до 32 символов; поддерживается 1.0.0 |
| features | Четыре конечных немасштабированных числа, без приведения строк/boolean |

Project/connection ID: до 128 ASCII-символов, буква/цифра в начале, далее буквы,
цифры, `.`, `_`, `:`, `-`. Схема и таблица: 1–255 символов, точное сравнение,
без обрезания пробелов и изменения регистра.

Ключ результата: **(project_id, connection_id, schema_name, table_name, ts,
model_version, feature_schema_version)**, где ts — нормализованный UTC observed_at.
Чтение API/дашборда явно выбирает обе версии. Повтор того же входа по полному
ключу идемпотентен; другая версия сохраняется отдельно. Смена/откат модели не
удаляет историю. Режим demo сохраняется с результатом.

Старым строкам не угадывают connection_id или версию: они остаются
`legacy-unknown`. Новые сборщики записывают полный источник в метрики и снимки
схемы. Переименование схемы/таблицы создаёт другой source; объединения истории нет.
Повреждённая конфигурация адаптера даёт контролируемый 503
`invalid_configuration`, включая основной API аномалий и страницу версий.
Дубликат одной точки одного источника даёт 409 `ambiguous_source` при
интерактивном чтении. Фоновый адаптер изолирует дубликат и следующую пару,
продолжает остальные точки и оценивает только отсутствующие результаты.

## Признаки

Вектор до scaler: `[row_count, null_rate, d_row_count, d_null_rate]`.
row_count >= 0; null_rate в [0, 1]; d_null_rate в [-1, 1].
null_rate — средняя доля NULL по колонкам, как в legacy-контуре.

Сначала точки совмещаются по UTC-времени. Дельты — разности с предыдущим
**доступным согласованным** наблюдением, без деления на длительность разрыва:
100 → 110 через час даёт d_row_count=10. Пропуски не заполняются нулями.
Нет предыдущей точки — адаптер отвечает 422 `insufficient_history`, не вызывает
сервис и не обучает модель.

Сервис проверяет previous_observed_at < observed_at, row_count - d_row_count >= 0,
null_rate - d_null_rate в [0, 1] с допуском на округление вычитания.
JSON Schema не сравнивает поля: эти проверки выполняет код.
FastAPI не вычисляет дельты повторно и использует scaler выбранного артефакта.

## Ответы и порядок ошибок

Полные примеры — в YAML; работающие запросы/ответы —
[evidence/smoke.json](../inference/evidence/smoke.json). Значения старого примера
`demo-if-2026-09-26` и score=-0.12 синтетические, не опубликованный эксперимент.
Архивный baseline #9 с FPR 13,27% разрешён только в явно отмеченном demo.

Успех содержит source, время, фактические версии, сырой score, threshold=0 и
**boolean** is_anomaly=(score < 0). Нулевая граница не является аномалией.
Сервис фиксирует одну пару модель/scaler на запрос; последний joblib не подставляет.

| HTTP | error.code | Условие |
|---|---|---|
| 400 | invalid_json | JSON не разбирается, глубина >32, NaN/Infinity/-Infinity или переполнение binary64 |
| 401 | authentication_required | Нет действительного токена; WWW-Authenticate: Bearer |
| 403 | source_forbidden | Полный источник не разрешён токену |
| 409 | feature_schema_mismatch | Неподдерживаемая схема или несовместимость с проверенным манифестом |
| 413 | request_too_large | Тело JSON превышает 64 KiB |
| 415 | unsupported_media_type | Content-Type не application/json |
| 422 | invalid_input | Типы, диапазоны, даты или межполевые ограничения |
| 503 | model_unavailable | Нет модели разрешённого источника, допуска, целостности или возможности загрузки |
| 500 | internal_error | Техническая ошибка без секретов/traceback |

Порядок `x-validation-order`: токен → Content-Type/лимиты и строгий JSON → структура →
доступ к source → поддержка схемы → межполевые правила → поиск модели и
целостность манифеста → совместимость схемы манифеста → загрузка модели/scaler.
Версия другого источника считается отсутствующей (503), её существование не
раскрывается. Повреждённый манифест даёт 503; целостный, но несовместимый — 409
до десериализации. Универсального приоритета 409 над 503 нет.

Политика `x-json-policy` реализована строгим декодером и проверкой конечности:
NaN/Infinity/-Infinity/1e400 дают 400, строка "110" или boolean вместо числа — 422.
`format: double` и `x-*` сами по себе не обеспечивают это в любом валидаторе;
поведение проверяется также реальными HTTP-тестами. RFC 3339 проверяется
`rfc3339-validator`, явно включённым в runtime-зависимости.

## Версии и совместимость

`info.version=1.1.0` — версия описания; `/v1/` — MAJOR интерфейса.
model_version и feature_schema_version имеют отдельный смысл.

- **MAJOR:** переименовать обязательное score в anomaly_score, изменить знак
  score/порог или потребовать новый обязательный признак. Нужен /v2/;
  изменение признаков требует новой схемы и совместимого артефакта.
- **MINOR:** новое необязательное поле processing_ms/demo в успешном ответе.
  Верхний уровень PredictionResponse допускает новые поля, обязательные сохраняются.
  Вложенный source и ошибка строгие: добавление полей туда нарушает контракт.
- Смена опубликованной модели с прежней схемой не меняет /v1/. Качество
  проверяется отдельно от HTTP.

При переименовании score дашборд перестал бы читать оценку; contract-test
отклоняет такой ответ. Необязательное верхнее поле допускается. Также проверяются
соответствие is_anomaly знаку score и связь error.code с HTTP-статусом.

## LLM и измерения

Требования к /api/explain согласованы с [аудитом #18](../LLM_LIMITATIONS.md):
авторизация и доступ до кэша, полный источник в ключе и контексте, миграции
SQLite/PostgreSQL, 400 при неверных типах. Три исходных XFAIL устранены в #12.
Защита от смысловых ошибок LLM этим не доказана; подробности в
[руководстве #12](../inference/README.md).

Предлагаемые p95-цели: legacy anomalies ≤500 мс (672 точки), legacy forecast ≤2 с
(прогретая линейная модель, 10 точек, horizon=1d), predict ≤100 мс (четыре признака,
прогретая модель). Доступность за период не измерена. Исходный профиль целей —
один worker, 2 vCPU/4 GiB, 1 запрос/с. Фактический локальный профиль и все 100
измерений находятся в smoke.json; это не замер на профиле SLA. Холодный запрос,
ошибки и время Flask/чтения истории учитываются отдельно.
